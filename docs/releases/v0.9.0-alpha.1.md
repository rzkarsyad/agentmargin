## AI audit supply-chain follow-up (unreleased)

Manual SDK publication is now split: the build job has no OIDC permission, uses
npm ci --ignore-scripts, runs checks and prepares the SDK plus exact npm 11.9.0 CLI
archive. The CLI SHA-512 is pinned in the workflow. Only the minimal npm job has
id-token:write under npm-publish; it checks artifact/CLI integrity and publishes
with lifecycle scripts disabled. It has no source checkout, dependency install or
repository test execution. Both jobs require dispatch from main in this repository;
the approved tag must equal the workflow's exact protected-main commit and have
passing final-commit test checks. No publication workflow was dispatched here.

This reduces token exposure, not every build-supply-chain risk: a compromised
builder could poison SDK output. Environment reviewers must inspect/approve the
artifact and verify npm trusted-publisher repository/workflow/environment binding.
Required reviewers, protected-main-only environment deployment rules, protected
SDK tags and publisher settings are operator gates; they are not inferred from
YAML or changed by this patch. The repository's active Protect main ruleset is
verified separately; it does not prove npm environment/tag restrictions.

Current-branch Actions are pinned to verified full commits. The official PostgreSQL
16 OCI index is pinned to 9e2cf6287f25c3151f4c9421ccce2b17f3e60061c111a29165e0d2cdd9ff0a97
and was verified to contain amd64 and arm64 descriptors. Browser Python packages
are exact CPython 3.12/Linux x86_64 wheels with required SHA-256 hashes. Actions
receive monthly Dependabot PRs; no automatic merge is configured. Each month or
on a security advisory, refresh image/node/browser/CLI/package pins in a review PR,
verify upstream identity and multi-architecture/platform compatibility, regenerate
hashes from the official release channel, run full checks/rehearsal, and inspect
SARIF before approval. Never replace a digest merely because a tag moved.
